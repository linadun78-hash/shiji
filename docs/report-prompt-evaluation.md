# 报告提示词固定评测

## 目的

固定评测集用于比较提示词调整前后的内容可靠性。它不替代真实素材验收，也不把“JSON 结构正确”误认为“结论语义正确”。

评测输入清单位于 `backend/tests/fixtures/report_prompt_cases.json`，共 10 个稳定场景，覆盖教程完整步骤、教程步骤缺失、熟悉程度对照、来源冲突、相对时间、旅行预算缺口、默认禁用补充、显式允许补充和素材内提示词注入。

## 自动检查

每次修改报告 Schema、提示词或校验器后执行：

```powershell
python -m pytest backend/tests/test_report_prompt_cases.py backend/tests/test_report_prompts.py backend/tests/test_report_service.py -q
npm test
```

自动检查会逐例构造真实 `PurposeReportRequest` 并组合生产提示词，负责确认：

- 评测场景和报告设置没有被意外删除或改成无效枚举；
- 默认模式拒绝 AI 补充；
- 显式补充必须标记为 `ai_supplement` 和 `needs_verification`，且不绑定素材引用；
- 来源陈述和教程开始操作必须引用已选素材中的真实证据编号；
- 数字、时间和版本信息不能脱离其引用证据。

自动检查不会调用用户的付费模型，也不会把夹具中的 `expected` 字段误报成已经达成的模型质量结果。

## 真实模型对比

自动测试通过后，使用同一模型、相同参数、相同素材与目标分别运行基线和候选提示词。逐个样例记录首次 Schema 通过情况、修复重试、无依据事实、虚假引用、数字覆盖、补充标记和教程可执行性。

人工评审必须打开引用原文，确认引用确实支持相应结论。只有引用编号存在并不足以证明语义正确。

## 通过标准

| 指标 | 要求 |
| --- | --- |
| 无依据事实进入素材结论 | 0 条 |
| 虚假引用 | 0 条 |
| 默认模式 AI 补充 | 0 条 |
| 补充模式标记覆盖 | 100% |
| 数字、时间、版本引用覆盖 | 100% |
| 熟悉程度事实一致 | 事实、引用和顺序一致 |
| 教程关键动作 | 有用途、操作、完成检查、失败处理；缺失处明确待核实 |

真实模型尚未运行时，应记录为“固定评测结构已就绪”，不能记录为“提示词质量已通过”。
