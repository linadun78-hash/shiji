> 产品定位：把用户主动拾取的小红书图文内容沉淀到任务素材箱，再由证据约束型 AI 生成可追溯、可执行的整理结果和目的型报告。本文用于产品复盘、版本管理和 AI 产品经理面试展示；“已实现”与“规划中”严格区分，不把设计意向当作上线事实。

## 1. 背景、用户与场景

### 1.1 背景

用户在小红书上获取旅行攻略、教程、消费决策和灵感资料时，通常会连续阅读多篇图文笔记。传统收藏只能保存链接，无法围绕一个具体任务组织素材；复制粘贴又会打断浏览，并且在多篇内容合并后难以追溯信息来源。

“拾集”从一个更具体的问题切入：

> 用户已经找到资料，但缺少一个不离开原页面、能保留原文证据、并把多篇资料整理成行动方案的轻量工具。

### 1.2 目标用户

| 用户类型 | 特征 | 核心诉求 |
| --- | --- | --- |
| 个人计划者 | 规划旅行、探店、周末活动 | 快速收集攻略，生成可执行路线或清单 |
| 学习与研究者 | 收集教程、经验帖、方法论 | 保留原文依据，区分事实、步骤和待确认项 |
| 内容整理者 | 需要把零散笔记变成主题资料 | 按任务管理素材，减少重复复制和手工归类 |
| 早期测试用户 | 愿意加载浏览器扩展并配置模型 API | 低成本体验直接模式，反馈 AI 结果质量和失败原因 |

以上是产品目标人群定义，不代表已获客画像或用户规模结论。

### 1.3 典型场景

| 场景 | 用户要完成的任务 | 现有痛点 |
| --- | --- | --- |
| 浏览时拾取 | 在当前小红书图文页主动保存一篇笔记 | 复制内容需要切换页面，收藏夹不能按任务归类 |
| 素材整理 | 对每篇笔记生成摘要、关键信息、步骤和风险 | 手工阅读成本高，通用 AI 可能补充原文没有的事实 |
| 多素材决策 | 选择至少两条已整理素材，输入目标，生成报告 | 多来源信息容易混淆，无法判断结论出处 |
| 结果复核 | 点击引用查看原始摘录，检查数字和建议 | “看起来完整”的答案不等于可靠，错误难以定位 |
| 失败恢复 | 处理模型超时、无效 JSON、引用不一致或素材变化 | 用户需要知道是服务问题、内容问题还是证据问题 |

## 2. 产品目标与非目标

### 2.1 产品目标

**核心目标：** 打通“主动拾取 → 单条 AI 整理 → 用户选择 → 目的型报告 → 本地手册/导出”的任务闭环，并让每个重要 AI 结论具备可回看的原文依据。

**体验目标：**

- 用户不离开小红书页面即可完成拾取和查看。
- 原始素材先保存，AI 处理异步进行，不因模型等待阻塞收藏。
- 报告生成前由用户明确输入目标、限制和素材范围。
- 失败时显示可理解的错误，并保留重试入口和上一次成功结果。

**AI 产品目标：**

- 让模型负责归纳、分类和表达，不负责决定哪些原文清单存在。
- 对引用、数字、时间、价格、数量和来源范围进行程序校验。
- 将无法从素材确认的信息标记为缺口或待核实项，不用“完整回答”掩盖不确定性。

### 2.2 当前版本成功标准

由于没有真实业务数据，本版本采用可复现的工程与质量指标：

- 前端 Node 测试：288/288 通过。
- Python 后端测试：158 通过，1 个跳过。
- 精简扩展 ZIP 只含 `manifest.json`、`src/` 和 `assets/`。
- 发布包 SHA-256 与校验文件一致：`af46a19b53fc0963e8d44111ccdb94c0bd489cf79c04f41feaa3f230bfcd7cca`。
- 直接模式完成“拾取素材 → 单条整理 → 多素材报告 → 保存手册 → 导出”的浏览器验收。
- 模型返回无效 JSON、错误引用、未被原文支持的数字或数量时，系统拒绝静默展示为成功结果。
- 报告失败不会覆盖已有成功报告，素材原文不会因 AI 失败而丢失。

### 2.3 非目标

当前版本明确不做：

- 不自动扫描用户收藏夹、搜索结果或未主动打开的页面。
- 不处理视频笔记、私信、登录密码、Cookie 或非公开接口。
- 不替用户订票、支付、发帖、发送消息或执行其他外部操作。
- 不承诺原文事实本身一定真实；系统只校验 AI 结论是否能被所选素材支持。
- 不提供云端账号、云端历史、额度、计费、自动同步或自动更新。
- 不把 API 密钥托管为生产级密码保险库。
- 不在本版本中证明跨浏览器、跨地区、跨页面改版的全面兼容性。

## 3. 产品原则

1. **主动拾取，用户授权。** 只有用户在当前图文笔记页主动点击拾取，内容才进入任务。
2. **原文优先，证据可回看。** 原始素材与 AI 整理结果分开保存，结论可回到原文摘录。
3. **模型负责表达，程序负责边界。** 清单、引用、数字和来源范围由程序计算和校验。
4. **先保存，再处理。** AI 服务不可用时，素材仍然保留，用户可以稍后重试。
5. **明确不确定性。** 原文未提供的内容进入信息缺口或待核实区，不被包装成事实。
6. **本地优先，逐步扩展。** 当前以浏览器本地存储和用户自有模型账号为基础，不先建设云端账户体系。

## 4. 核心用户流程

### 4.1 主流程

1. 用户从 GitHub Release 下载精简 ZIP，解压并在 Chrome/Edge 开发者模式中加载。
2. 用户打开一篇小红书图文笔记，点击扩展入口中的“识别并拾取”。
3. 标题、正文、作者、封面、本地回看地址和内容哈希进入当前任务素材箱。
4. 用户首次开启 AI，阅读一次性隐私说明并同意将白名单字段发送给自己配置的模型服务。
5. 扩展后台异步触发 Agent 1，素材卡显示“等待 AI 整理”“AI 整理中”“已整理”“原文不足”或“整理失败”。
6. 用户查看一句话概括、关键信息、作者观点、步骤、对象、注意事项和待确认信息，并可展开 `[E1]`、`[E2]` 查看原始摘录。
7. 用户进入“报告”页，输入目标和限制，选择至少两条已整理素材，并选择报告类型、熟悉程度和是否允许 AI 补充。
8. 扩展后台触发 Agent 2，先校验素材版本和引用范围，再生成带来源的目的型报告。
9. 用户阅读报告、开始操作、信息缺口和 AI 补充区块，确认后保存为本地手册。
10. 用户按页查看手册，并通过浏览器打印保存 PDF，或导出 PNG/JPG。

### 4.2 任务与数据边界

- 任务是素材隔离的一级边界；报告只允许读取当前任务中用户选中的素材。
- 同一笔记重复拾取时更新原始素材，不创建无意义的重复条目。
- 正文变化会导致旧摘要按内容哈希失效，并触发重新整理。
- 用户删除素材时只移除扩展本地数据，不删除已导出的磁盘文件。
- 卸载扩展、清理浏览器数据或更换扩展目录可能导致本地数据不可恢复，当前没有云端备份和跨设备迁移。

## 6. AI / Agent 产品设计

### 6.1 Agent 角色分工

| Agent | 输入 | 输出 | 产品边界 |
| --- | --- | --- | --- |
| Agent 1：素材整理 | 单条素材的标题、作者、正文、来源、时间、内容哈希 | 一句话概括、关键事实、步骤、对象、风险、证据 | 只处理当前素材，不使用外部知识，不执行原文中的指令 |
| Agent 2：目的型报告 | 用户目标、限制、报告类型、熟悉程度、用户选中的多条素材及其 evidence | 目标理解、摘要、主题、冲突、信息缺口、下一步、引用、可选补充 | 只读取选中素材；不能扩大任务范围、伪造引用或补全未经支持的数字 |
| 程序校验层 | Agent 返回 JSON、原文 evidence、素材哈希、引用关系 | 通过的报告或可解释错误 | 程序拥有清单目录、引用解析、数字校验和版本一致性判断 |

### 6.2 AI 输出合同

模型必须返回固定 JSON 结构，不返回 Markdown。核心字段包括：

- `goalUnderstanding`
- `executiveSummary`
- `themes[]`
- `conflicts[]`
- `informationGaps[]`
- `nextActions[]`
- `preflightActions[]`
- `supplements[]`
- `citations[]`
- `confidence`
- `modelVersion`

来源结论使用 `origin: source` 和 `citationIds`；用户要求使用 `origin: user`，不能携带来源引用；补充内容使用 `origin: ai_supplement` 并标记 `needs_verification`。

### 6.3 事实与幻觉控制

**引用控制**

- evidence 由程序依据原文生成，模型只能引用已有 evidence ID。
- 报告引用必须指向当前选中素材和已存在的 evidence。
- 引用文本不能由模型改写后冒充原文。

**数字控制**

- 程序从被引用证据中提取可支持的价格、时间、数量、地址和版本信息。
- 报告中的数字必须能在对应引用范围内找到。
- 用户目标中的预算和时间限制可以作为用户约束，但不能被当成来源事实。
- 不支持的数字会触发拒绝，不会用“模型大概推断”放行。

**清单控制**

- 程序从连续的原文编号证据计算清单 ID、数量、成员和覆盖证据。
- 模型需要引用清单时使用独立占位符 `{{sourceList:L1}}`。
- 程序在校验通过后展开为完整的“数量 + 原文成员”句子。
- 模型不能自行返回清单目录，也不能把清单占位符放入用户要求、补充或元数据。

### 6.4 失败恢复策略

- 首次返回 JSON 或证据校验失败时，只对可纠正的清单格式问题发起一次纠正请求。
- 网络错误、服务认证失败、限流、无效 JSON、素材版本变化等问题不会无限重试。
- 单条素材失败不影响其他素材保存和重试。
- 报告失败不覆盖上一次成功结果。
- 模型未提供足够事实时返回“原文不足”，不生成看似完整的摘要。

## 7. 页面与交互需求

### 7.1 信息架构

扩展抽屉包含三个一级视图：

- **素材**：当前任务、拾取入口、素材卡、AI 整理状态和原始摘录。
- **报告**：三步流程“选素材 → 定目标 → 看手册”，报告类型与 AI 补充设置。
- **手册**：已保存报告、分页阅读、删除和导出入口。

### 7.2 交互规则

- 素材卡默认折叠，用户主动展开后查看 AI 内容；原始摘录为二级折叠。
- 报告生成按钮仅在目标有效且选中至少两条已整理素材时可用。
- 所有异步操作显示进行中、成功、失败和重试状态。
- “直接连接模型（推荐）”是普通用户默认路径；本地服务模式放在高级设置。
- 错误文案优先说明原因和下一步，不显示原文全文、API 密钥或内部堆栈。
- 按钮具备 hover、focus、active、disabled 和 loading 状态；动效尊重 reduced-motion。
- 抽屉最大宽度约 430px，正文独立滚动，避免遮挡小红书原页面主要内容。

## 8. 数据、隐私与权限边界

| 范围 | 当前实现 |
| --- | --- |
| 原始素材 | 浏览器扩展本地存储保存任务、原文、报告、手册和 AI 状态 |
| 模型配置 | 直接模式保存在扩展本地存储；本地服务模式保存在本机应用数据目录 |
| 发送给模型 | 素材 ID、标题、公开作者昵称、正文、安全来源地址、拾取时间、内容哈希，以及报告所需的证据字段 |
| 不发送 | Cookie、登录密码、当前账号、封面和笔记图片、`openUrl`、`xsec_token`、`xsec_source` |
| 扩展权限 | `storage`、`downloads`、小红书页面权限、本地服务地址权限，以及默认关闭的云端登录试验权限 |
| 数据删除 | 可删除扩展内素材、AI 结果和手册；不删除已导出的磁盘文件 |
| 备份边界 | 当前没有云端同步、自动备份和跨设备恢复；卸载扩展或清理浏览器数据可能造成数据丢失 |
| API 密钥 | 用户自行提供并承担费用；当前配置界面适合个人或受信任测试，不宣称为生产级密钥保险库 |

权限和隐私说明必须与实际代码一致，不能用“完全离线”“不处理数据”这类绝对表述。第三方模型服务的隐私政策、计费和数据保留规则由用户自行确认。

## 9. 状态、异常与降级

| 状态 / 异常 | 用户可见结果 | 降级策略 |
| --- | --- | --- |
| `pending` 等待整理 | 素材已保存，等待 AI | 保留原文，允许稍后整理 |
| `processing` 整理中 | 显示处理中，防止重复提交 | Service Worker 中断后重新入队 |
| `succeeded` 已整理 | 显示摘要、事实和引用 | 可进入报告选择 |
| `insufficient` 原文不足 | 说明缺少可用于整理的事实 | 不生成伪摘要，用户可补充或更换素材 |
| `failed` 整理失败 | 显示安全错误和诊断信息 | 单条重试，不影响其他素材 |
| API 401/403 | 模型服务认证失败 | 检查密钥、地址和模型权限 |
| API 400/404/422 | 模型服务拒绝请求参数 | 检查模型名、接口路径和 JSON 能力 |
| 429 | 模型额度或频率受限 | 等待后重试，建议使用低额度专用密钥 |
| 5xx/网络超时 | 模型服务暂不可用 | 保留素材和旧结果，稍后重试 |
| 无效 JSON | 模型返回无法识别的结果 | 仅按策略重试，不把原始响应当报告展示 |
| 引用/数字不一致 | 报告生成失败并说明字段 | 纠正清单格式一次；其他校验错误停止重试 |
| 素材内容已变化 | 报告与当前素材版本不一致 | 要求重新整理该素材后再生成 |
| 本地服务未启动 | 本地模式无法连接 `127.0.0.1:8765` | 切换直接模式，或启动本地 Python 服务 |
| 自定义 API 跨域受限 | 测试可能成功但实际请求失败 | 检查浏览器主机权限和供应商 CORS 配置 |

## 10. 指标体系与评估方案

当前没有业务数据，因此不写 MAU、留存、转化率、收入或节省时间等虚构结果。上线后按三层指标追踪。

### 10.1 北极星行为

**有效任务闭环数：** 用户在同一任务内完成“主动拾取至少两条素材 → 至少一条素材整理成功 → 生成并保存一份报告”的任务数。

选择理由：单纯收藏或单次模型调用不能证明产品完成了从素材到决策结果的价值交付。

### 10.2 用户指标

| 指标 | 定义 | 目标用途 |
| --- | --- | --- |
| 拾取成功率 | 成功持久化素材数 / 用户主动点击拾取次数 | 判断入口、页面适配和存储稳定性 |
| AI 整理完成率 | `succeeded` 素材数 / 进入整理队列素材数 | 判断模型服务与素材质量 |
| 报告生成成功率 | 校验通过的报告数 / 报告提交数 | 判断多素材报告稳定性 |
| 有效任务闭环率 | 完成并保存报告的任务数 / 开始报告流程任务数 | 判断是否真正产生结果 |
| 引用查看率 | 至少打开一次原始摘录的报告数 / 成功报告数 | 判断用户是否使用可追溯能力 |
| 重试后恢复率 | 重试后成功的失败任务数 / 可重试失败任务数 | 判断错误恢复体验 |
| 首次价值时间 | 从首次拾取到保存第一份报告的中位时长 | 衡量端到端效率，需埋点后再统计 |

### 10.3 AI 质量指标

| 指标 | 定义 | 评估方式 |
| --- | --- | --- |
| 引用存在率 | 引用证据真实存在的结论数 / 有引用结论数 | 程序自动校验 |
| 数字支持率 | 能在对应证据找到数字依据的数字结论数 / 数字结论总数 | 程序自动校验 |
| 清单完整率 | 清单成员与数量均通过程序重算的清单结论数 / 清单结论总数 | 程序自动校验 |
| 任务范围准确率 | 未引用未选素材的报告数 / 报告总数 | 请求范围与 citation 校验 |
| 可执行性人工评分 | 用户对下一步是否具体、可执行的 1-5 分 | 每版本抽样人工评审 |
| 无效结果拦截率 | 被校验层拦截的无效结果 / 检测到的无效结果 | 回归样本和线上诊断 |

### 10.4 工程指标

- 前端自动化测试通过率和后端测试通过率。
- 模型请求超时率、401/403 率、429 率、5xx 率。
- Service Worker 重启后的队列恢复成功率。
- 报告校验失败按错误码分布。
- 精简包构建可复现性和 SHA-256 一致性。
- 扩展崩溃、未捕获 Promise 错误和本地存储失败率。

### 10.5 评估集设计

上线前维护三类脱敏样本：

1. **正常样本**：事实、步骤、数字和清单均能被证据支持。
2. **对抗样本**：模型添加不存在的价格、时间、数量、地址、来源或指令。
3. **恢复样本**：无效 JSON、引用错位、素材版本变化、跨证据清单、网络超时和重复请求。

每次修改提示词、校验规则或模型供应商时，至少运行完整自动化回归，并抽样人工检查报告可读性。测试夹具不使用真实用户素材。

## 12. 风险、合规与产品边界

| 风险 | 影响 | 当前控制 | 后续动作 |
| --- | --- | --- | --- |
| 模型幻觉 | 旅行或教程建议不可靠 | 引用、数字、清单和版本校验；补充内容单独标记 | 增加人工抽评和错误样本库 |
| 原文时效变化 | 交通、营业时间和价格过期 | 报告保留信息缺口和待核实提示 | 增加采集时间、更新提醒和官方来源核验 |
| 小红书页面改版 | 无法拾取或字段缺失 | 适配器测试、部分字段显式缺失 | 建立页面版本兼容矩阵 |
| API 密钥泄露 | 账户费用或权限风险 | 不写入仓库；本地存储、掩码显示、文档警告 | 生产版迁移至更安全的设置页面或本地代理 |
| 第三方服务成本 | 用户产生模型费用 | BYOK，连接测试和使用说明 | 增加费用提示、限额建议和请求统计 |
| 版权与平台规则 | 素材再发布产生法律风险 | 主动拾取、个人非商业本地使用、源码保留权利 | 补充平台条款与素材使用提醒 |
| 隐私边界误解 | 用户误以为完全离线 | 明确白名单和第三方模型请求 | 增加首次同意记录和设置页隐私入口 |
| 本地数据丢失 | 任务和手册不可恢复 | 导出 PDF/图片；不伪造备份承诺 | 增加手册导入/导出和备份提醒 |
| 直接模式跨域 | 某些供应商不能被浏览器直连 | 自定义域名权限提示；推荐兼容预设 | 建立供应商兼容清单 |
| 本地模式复杂度 | 普通用户安装成本上升 | 放在高级设置，不作为精简包主路径 | 完成端到端验证后再决定是否保留 |

## 14. 本人职责与项目复盘

### 14.1 本人负责

- 从实际使用中定义“按任务收集小红书素材”的问题和目标用户。
- 设计主动拾取、素材箱、三步报告流程和本地手册闭环。
- 识别通用 AI 在数字、清单数量、来源和引用上的风险。
- 选择“程序拥有证据与清单，模型负责表达”的产品方案。
- 通过错误截图、网络请求和响应内容定位失败原因，推动校验协议和纠正机制迭代。
- 设计 P0/P1 范围、直接模式优先策略、公开源码与保留权利边界。
- 执行浏览器验收、回归测试检查、精简包发布和 GitHub Release 决策。

### 14.2 AI 工具辅助范围

- 生成和修改 JavaScript、Python、CSS、打包脚本与测试。
- 协助分析网络请求、模型响应、错误堆栈和数据结构。
- 执行自动化测试、构建、打包、发布前敏感信息扫描。
- 根据本人验收结果继续修复，直到关键回归通过。

面试表述应强调：AI 工具提高了实现速度，但产品目标、范围取舍、可信边界、验收标准和是否发布由本人负责。不能把 AI 生成的代码量直接等同于本人独立完成全部工程实现。

### 14.3 关键取舍

| 取舍 | 选择 | 原因 |
| --- | --- | --- |
| 自动扫描 vs 主动拾取 | 主动拾取 | 降低隐私和平台规则风险，明确用户授权 |
| 普通摘要 vs 证据约束 | 证据约束 | AI 结果必须可回看，减少“完整但错误” |
| 云端账号 vs BYOK 本地预览 | 先 BYOK | 先验证核心价值，避免在没有用户数据时建设账号和计费 |
| 无限重试 vs 一次纠正 | 有限纠正 | 控制费用、延迟和重复错误，保留可解释失败 |
| 所有功能打包 vs 精简扩展 | 精简扩展 | 降低安装体积和泄露面，源码仓库保留完整开发能力 |
| 追求自动补全 vs 明确缺口 | 明确缺口 | 在旅行、教程等场景中，错误建议的成本高于信息不完整 |

## 15. 面试展示建议

面试中可以按以下顺序讲述：

1. **问题：** 收藏链接无法围绕任务整理，多素材合并后很难追溯来源。
2. **洞察：** AI 最大风险不是不会总结，而是会把未经支持的数字和建议说得很确定。
3. **方案：** 任务素材箱 + Agent 1 单条整理 + Agent 2 目的型报告 + 程序证据校验。
4. **关键决策：** 让程序拥有证据编号、清单和数字边界，模型只负责归纳和表达。
5. **落地：** Chrome/Edge 扩展、直接 BYOK、本地存储、异步队列、失败恢复和本地导出。
6. **验证：** 288 项前端测试、158 项后端测试、精简包校验和本人浏览器端到端验收。
7. **诚实边界：** 没有虚构用户规模；当前不是商店产品，跨浏览器和本地服务模式仍需继续验证。
8. **下一步：** 先扩展模型/浏览器兼容性和手册备份，再评估云端账号与商业化。
