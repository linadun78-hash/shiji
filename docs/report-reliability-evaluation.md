## 可断点续跑的执行方式

浏览器取材、模型验收和页面验收必须分开执行。先从扩展当前任务导出真实素材为 JSON，不在运行模型时继续打开或刷新浏览器。夹具结构如下：

```json
{
  "goal": "整理广州秋季一日游路线",
  "constraints": ["预算不超过500元", "优先公共交通", "避免过度拥挤"],
  "materials": [
    {
      "materialId": "真实素材ID",
      "title": "真实标题",
      "author": "页面公开作者名",
      "bodyText": "真实读取正文",
      "sourceUrl": "不含临时令牌的公开原文地址",
      "capturedAt": "2026-08-19T10:00:00Z",
      "contentHash": "v1-1234abcd"
    }
  ]
}
```

运行命令：

```powershell
D:\Anaconda\python.exe scripts\run_reliability_acceptance.py `
  --fixture tmp\acceptance\guangzhou-five-materials.json `
  --checkpoint tmp\acceptance\guangzhou-five-results.json
```

- Agent 1 严格串行执行；现有模型客户端的单次读取上限为 60 秒。
- 每条素材结束后立即原子写入检查点；再次运行会跳过 `materialId + contentHash` 相同的成功或信息不足记录，失败记录会重试。
- 至少两条素材成功后才调用 Agent 2；相同目标、限制和素材哈希已有成功报告时直接复用。
- 检查点只记录模型名称，不保存 API Key、Cookie 或浏览器临时令牌。
- 每次模型调用前后比较全部 `rundll32.exe` PID；任何变化都会先写入 `aborted` 状态，再停止后续调用。
