# 真实小红书图文笔记验证清单

## 验证目的

用真实笔记回答三个问题：

1. 入口能否在用户正常浏览流程中出现。
2. 当前页面能否稳定读取对后续任务有用的字段。
3. 素材能否正确进入任务、恢复、更新和删除。
4. 用户一次同意后，Agent 1 能否非阻塞整理单条素材并给出可回看原文的引用。

本轮同时检查原始素材链路、Agent 1 单条整理和 Agent 2 跨素材报告，不使用演示页数据替代真实结果。Agent 1 与 Agent 2 的质量指标分开记录。

## 样本选择

选择 10 至 20 篇本人有权正常查看的图文笔记：

- 4 至 6 篇从搜索结果进入。
- 4 至 6 篇从自己的收藏列表进入。
- 2 至 4 篇通过直接链接进入。
- 至少 2 篇正文较短。
- 至少 2 篇包含多张图片。
- 如能找到，加入 1 至 2 篇已失效或访问受限的笔记验证失败状态。

视频笔记不计入本轮成功率。

## 单篇记录表

每篇笔记记录以下结果：

| 编号 | 进入路径 | 入口出现 | 标题 | 作者 | 正文 | 封面 | 原文链接 | 状态正确 | 备注 |
|---|---|---|---|---|---|---|---|---|---|
| 01 | 搜索/收藏/直链 | 成功/失败 | 正确/错误/缺失 | 正确/错误/缺失 | 正确/错误/缺失 | 正确/错误/缺失 | 正确/错误 | 是/否 | 页面特征或失败原因 |

字段正确的判断以当前页面肉眼可见内容为准。页面本身没有显示的内容应记为“缺失”，不能记为解析错误。

## 功能检查

- [ ] 非笔记页面显示“打开图文笔记后可拾取”，不会误保存页面。
- [ ] 图文详情加载后，按钮变为“识别并拾取”。
- [ ] 点击一次后素材数量增加 1，素材箱自动打开。
- [ ] 完整字段显示“完整文本”。
- [ ] 缺少正文、作者或封面时，缺失字段与实际情况一致。
- [ ] 展开预览可看到真实读取正文，不是硬编码演示内容。
- [ ] 展开“查看原始摘录”可看到真实正文和 AI 引用片段，不是硬编码内容。
- [ ] “打开原文”回到正确笔记。
- [ ] “打开原文”不会因丢失 `xsec_token` 而跳到扫码页；若平台仍要求验证，在备注中记录笔记类型和进入路径。
- [ ] 同一任务重复拾取同一笔记时数量不增加，标题或正文会更新。
- [ ] 同一笔记可分别加入两个不同任务。
- [ ] 切换任务后，素材列表与数量同步变化。
- [ ] 刷新小红书页面后，任务与素材仍存在。
- [ ] 移除单条素材后，列表、数量和本地状态一致。
- [ ] 清空当前任务不会清空其他任务，也不会影响小红书收藏。
- [ ] 页面快速切换时不会出现重复的悬浮入口。
- [ ] 控制台没有未处理错误。

## Agent 1 场景检查

- [ ] 首次显示“开启 AI 自动整理”，隐私说明准确列出素材 ID、标题、公开作者昵称、正文、安全来源地址、拾取时间和内容哈希会发送；当前登录账号、Cookie、回看地址和图片不会发送。
- [ ] 未点击“开启”前，素材显示“开启 AI 后整理”，不会产生模型请求。
- [ ] 点击“开启”后隐私说明不再重复出现，已有待处理素材按顺序整理。
- [ ] 新拾取素材先立即进入素材箱；关闭素材箱或继续浏览时不等待模型完成。
- [ ] 完整正文依次显示“等待 AI 整理”“AI 整理中”“已整理”。
- [ ] 成功卡片显示一句话概括和适用的关键信息、观点、步骤、对象、注意事项、待确认信息。
- [ ] 每条模型结论都附带 `[E1]`、`[E2]` 等引文编号，且引文内容逐字存在于正文；这只验证引文存在，不代表语义支持已被机器保证。
- [ ] 人工抽查每条结论，判断引文是否充分支持该结论，并单独记录支持不足的情况。
- [ ] 正文不足时显示“原文不足”，不生成摘要，也不删除原始素材。
- [ ] 模型超时或后端服务未启动时显示“整理失败”，原始素材仍可预览和打开。
- [ ] 恢复后端后点击“重新整理”，状态重新进入队列并最终写回。
- [ ] 同一笔记原文未变化时重复拾取，不重复生成已成功的摘要。
- [ ] 同一笔记标题或正文变化时重复拾取，内容哈希变化，旧摘要被清空并重新整理。
- [ ] AI 整理过程中删除素材，过期结果不会重新创建已删除素材，分析记录随后被清理。
- [ ] 在标签页 A 拾取后关闭详情页，在标签页 B 打开素材箱，后台结果仍能写回并展示。
- [ ] 同时拾取两条素材时，模型请求按拾取时间单并发执行。
- [ ] 停止并重启扩展 Service Worker 后，原“AI 整理中”记录回到等待队列，不永久卡住。

## Agent 2 场景检查

- [ ] 标题栏齿轮可进入设置页，测试连接与保存状态明确；刷新后地址和模型名恢复，密钥不回显。
- [ ] 素材卡默认折叠，单卡展开不导致焦点跳走；全部展开和全部折叠可用。
- [ ] 报告页只列出当前任务中 Agent 1 已成功的素材，少于两条时不能生成。
- [ ] 填写明确目标并选择素材后，报告包含目标理解、总览、主题、冲突、信息缺口、下一步和来源。
- [ ] 展开来源能看到素材标题与真实引用片段，不只是内部编号。
- [ ] 生成期间切换任务，结果仍写回发起任务，不会覆盖另一任务报告。
- [ ] 删除或更新报告所用素材后，旧报告标记为过期但仍保留；生成失败不覆盖旧报告。
- [ ] 使用至少 5 组真实任务人工核验引用是否支持结论，并单独记录严重事实错误。

## 旅行报告可靠性检查

- [ ] 目标明确包含“旅行 / 旅游 / 行程”等旅行意图时，报告使用旅行手账五页；“求职攻略”“职业路线”等非旅行目标仍使用通用手册。
- [ ] 第 1 页显示目标、摘要、用户限制与所选素材，不补写素材中不存在的日期、预算或同行人。
- [ ] 第 2 页按 Agent 2 的行动顺序展示行程草案，不擅自生成具体日期或时间。
- [ ] 第 3 页的取舍理由标记为“素材依据”，每项保留来源编号，不宣称用户已经采用。
- [ ] 第 4 页只把带来源编号的金额列为预算依据；无引用金额不得进入预算表。
- [ ] 第 5 页同时显示冲突、待核实项、用户确认清单和可展开来源目录。
- [ ] 切换任务后，各任务保存的目标和限制分别恢复，不串用上一任务输入。
- [ ] PDF 与扩展内“导出图片”使用相同五页旅行布局；PNG/JPG 不丢失第 5 页长内容。
- [ ] 图片导出只生成选中的页，文件名保留原页码（例如第 2、5 页生成 `shiji-report-page-02.*`、`shiji-report-page-05.*`）。
- [ ] 图片导出过程中不请求 `/api/v1/experimental/workbook-images`，不要求启动 Uvicorn，也不产生中间 PDF。
- [ ] 复用 2026-08-17 的五条广州素材；只有四条事实素材进入 Agent 2 候选，纯提问与标签素材显示为信息不足。
- [ ] “未来一周”等相对时间保持来源相对语义，并要求核验发布时间后再使用。
- [ ] 交通、餐饮或门票存在缺口时，不得直接断言预算一定充足。
- [ ] 来源没有准确时间时，路线行动使用“时段待确认”，不能自行补具体时段。
- [ ] 缺失价格、时长或营业时间进入信息缺口；只有互相矛盾的来源才进入冲突。
- [ ] 报告中的每个数字、路线和时间主张都能展开到对应的原文引用片段。

## 隐私检查

- [ ] 浏览器网络面板中的请求体只有 `materialId`、`title`、`author`、`bodyText`、`sourceUrl`、`capturedAt`、`contentHash`。
- [ ] 请求体不包含 `openUrl`、`xsec_token`、`xsec_source`、Cookie、账号、封面或图片 URL。
- [ ] 后端 422 错误不会回显含令牌的非法输入。
- [ ] 扩展权限中没有 `cookies`、`tabs`、`webRequest` 或 `<all_urls>`。

## 指标计算

- 入口注入成功率 = 出现可用入口的图文详情数 / 可正常打开的图文详情总数。
- 必填字段正确率 = 标题、原文链接、任务归属正确次数 / 对应检查总次数。
- 可选字段读取率分别计算作者、正文和封面，不合并成一个模糊成功率。
- 状态准确率 = “完整/部分/失败”与人工核对一致的素材数 / 总拾取数。
- 去重正确率 = 重复拾取后只保留一条且内容更新的次数 / 重复测试次数。
- 恢复成功率 = 刷新后仍完整恢复任务与素材的次数 / 刷新测试次数。
- 自动整理成功率 = 成功样本数 / 完整正文样本数。
- 引文存在率 = 引文能逐字在正文中找到的结论数 / 带引文结论总数；此项由系统确定性校验。
- 人工支持率 = 经人工判断、引文充分支持的抽查结论数 / 人工抽查结论总数。

## 基础版通过条件

- 标题、原文链接和任务归属必须全部正确。
- 去重、刷新恢复、单条移除和分任务显示必须全部通过。
- 作者、正文或封面缺失可以降级，但状态必须如实说明。
- 不得出现硬编码报告、虚构字段或未点击即自动保存。
- Agent 1 结构校验和引文存在率必须 100%，完整正文自动成功率不低于 90%，人工支持率不低于 95%，严重事实错误为 0。

如果必填字段错误，先修页面适配器；如果 Agent 1 未达到质量门槛，保留失败样本并继续改进，不开始 Agent 2。
